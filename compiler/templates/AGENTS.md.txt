# AGENTS.md — working on `{name}`

This is a brine project. brine is a compiled,
verified, natively parallel language with Python-like syntax.

## Commands
- `brine check` — type-check and verify (fast; run after every edit)
- `brine run` — build and run `src/main.br`
- `brine test` — run all `test "...":` blocks
- `brine fmt` — format all sources (always run before committing)
- `brine guide` — the full language reference (read it once)
- `brine explain <CODE>` — explanation of any error code, e.g. `brine explain E0601`

Add `--json` to any command for machine-readable output (one JSON object per line).

## Rules that commonly trip people up
- `let` is immutable, `var` is mutable; no shadowing.
- No implicit numeric conversions: write `float(i)`, `int(x)`.
- Arguments are passed by value. A function that changes the caller's variable
  declares `ref x: T` and callers write `f(ref x)`; methods use `ref self`.
- `requires`/`ensures`/`invariant`/`prove` must be proven at compile time.
  If the prover can't, the error lists the known facts and often values it
  can't rule out: fix the code if they can happen, else add the fact that
  excludes them (an `invariant`, a `requires`, or an `assert`, a runtime check
  that becomes a known fact). Never weaken a contract just to make it pass.
- `brine check --report` lists the runtime checks that remain. With
  `proven = true` under `[check]` in brine.toml, each one is an error (E0607).
- Inside `par for i in a..b:` you may only write outer arrays at `out[i]` (or
  `out[k * i + c]` with constants `k >= 1` and `c`), and a `par` body can't
  write files, run processes or read stdin, even through a function it calls.
- Maps: `m[k]` panics if `k` is missing; test with `k in m` or use `m.get(k)`.
- No negative indexes (`xs[-1]` is an error); write `xs[len(xs) - 1]`.
- Strings index and slice by bytes; `s[i]` is a one-character `str`.
- One expression can't change a variable and also read it, or change it twice
  (`print(xs.pop(), xs)`, `f(xs.pop(), xs.pop())`); split it into two statements.
  A call inside another call's arguments runs first, so `xs.push(xs.pop())` is fine.
  Uses on different sides of `and`/`or`/`if-else` are fine.
- Types are optional (`let x = 5` or `let x: int = 5`); if brine.toml has
  `typed = true` under `[check]`, every `let`/`var`/`for` variable needs one.
- `match` must cover every case; read enum variant data with `match`, not `.field`.
- Expected failures return `Result[T, E]` (`Ok(x)` / `Err(e)`) or `Option[T]`
  (`Some(x)` / `None`); `panic` is for bugs. `x?` passes a failure up to the caller.
